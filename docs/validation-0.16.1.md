# 0.16.1 / DSH RC.3 验证范围

日期：2026-10-24。目标为官方 DSH `0.2.1-rc.3`（tag `dsh-v0.2.1-rc.3`），使用公开 npm 运行时和 Windows / Node 24。

## 问题与修复

在公开 PPT 0.16.0 的真实 Web 面板中复现：选择目录中的模型后，更新目录再点击“刷新视觉模型”，序号被重新解释为另一个模型，开始按钮仍可用。RC.3 让官方 API Key 路由跟随动态模型列表，使目录变动成为正常使用场景。

0.16.1 的视觉检查、AI 预审和模拟答辩统一按提供方及模型 ID 保存选择。重排、改显示名称不会改路由；原路由消失就清空选择并禁用开始按钮。没有可用的工程模型时，首次打开也要求明确选择，不自动采用列表首项。

## 自动检查

- Windows 完整测试通过，新增 6 项模型选择回归，覆盖目录重排、路由删除、空选择、精确初始偏好、提供方与分隔符碰撞、显示名称变化。
- TypeScript 构建、浏览器脚本语法和 diff 空白检查通过。

## 发布包与真实浏览器

- 候选 npm tarball 通过官方 CLI 安装到全新隔离 Web profile；普通生成器生成四页 PPTX、HTML 和 JSON 作为界面夹具。
- Browser plugin not available；使用已安装的无头 Chrome / Playwright，不切换用户前台窗口。
- 1440×1000 中文界面实际操作三处选择器：模型消失后选择清空且开始按钮禁用；视觉检查和 AI 预审的目录重排保留原路由，切换到模拟答辩也保留选择。仅文字模型不进入视觉模型列表。
- 390×844 英文深色界面：占位选项、刷新和禁用状态正常；PPT 面板 clientWidth / scrollWidth 均为 366px，无横向溢出。页面未捕获异常为 0。
- 模型目录变化由注册进官方 LLM 服务的隔离适配器控制。它没有 API Key、外网请求或模型生成能力；目录切换验收期间生成调用数为 0。这是接口与交互验收，不是实际 DeepSeek 模型效果验收。

## 其他插件与边界

- 既有 Suite 0.2.35 的 18 组件在官方 RC.3 上通过契约与公开 npm 全新安装，19 个包的完整性匹配；实际共同启动为 112 个工具、36 项技能，PTC、完整 SDK 及四个官方调度工具可用，认证检查为 303 / 401 / 200。
